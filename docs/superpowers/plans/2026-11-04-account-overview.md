# Account Overview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an account-wide `/overview` page showing what is broken right now
across every organization the user belongs to, plus how long things were
broken over 24h, 7d, 30d, or 90d.

**Architecture:**

- A new `check_outages` table holds one row per stretch of `DOWN` time. A
  Postgres trigger on `checks.status` maintains it, and two migrations create
  it and backfill it from history.
- A new NestJS `overview` module answers a single `accountOverview` query.
  Its service handles I/O, and a pure aggregation function does the math.
- A new client page renders the needs-fixing list, stat tiles, and four
  charts from that one query.

**Tech Stack:** PostgreSQL 18, Prisma 6, NestJS 11 code-first GraphQL, Jest,
Vitest, Next.js 16, Apollo Client 4, recharts 3, shadcn/ui on Base UI,
Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-11-04-account-overview-design.md`.
Read it before starting any task. Its Definitions section is binding.

## Global Constraints

- Node.js 22 and npm. Run each project's validation from its own directory,
  exactly as `AGENTS.md` lists it.
- Work on a feature branch named `feat/account-overview`, never on `main`.
- **Timestamps:** every DB column is `TIMESTAMP(3)` without time zone and
  holds UTC. All trigger and migration SQL must write
  `(now() AT TIME ZONE 'UTC')` or `(clock_timestamp() AT TIME ZONE 'UTC')`,
  never bare `now()`.
- **Outage row IDs** are generated by the database
  (`gen_random_uuid()`, `@db.Uuid`), because the trigger inserts them. Prisma
  code never creates outage rows.
- **GraphQL durations:** every `*Seconds` field in the overview types is
  GraphQL `Float` holding whole seconds. Never `Int`, because account totals
  can exceed Int32.
- **Don't expose creator identity:** overview organizations expose only
  `id`, `name`, and `slug`. Do not reuse `OrganizationModel`, which carries
  `creatorLabel`.
- `agentInstructions` is never rendered on the overview page.
- `api/src/schema.gql` is committed and regenerated by booting the API
  (`npm run test:e2e` does this). Commit it with every API change.
  `frontend/lib/graphql-documents.test.ts` validates frontend documents
  against it.
- **Duration display:** use the existing `formatElapsed(ms)` from
  `frontend/lib/format.ts`. It already produces `1d 6h`, `3h 12m`, `18m`,
  and `45s`.
- **Status colors:** DOWN uses `--destructive` and LATE uses `--warning`.
  Never use them for other meanings, and always pair them with a text label.
- No `window.alert`, `confirm`, or `prompt`. Show errors with the shadcn
  Dialog pattern (`errorMessage` state).
- Commit messages end with the session attribution lines from the
  conversation's system reminder.

## Review Focus

Each item has a pinning test in the task that owns it:

1. **An account with no organizations or no checks.** The API returns zeros
   with `uptimePercent: null` and never divides by zero, and the page shows
   the matching empty state. Covered by Task 3 `returns nulls when there is
   nothing to measure` and Task 5 `shows the no-checks empty state`.
2. **A check created in the middle of the range.** Its monitored time starts
   at `createdAt`, so a check that is new and down shows low uptime, not
   99%. Covered by Task 3 `starts monitored time at createdAt`.
3. **An ongoing outage that began before the range.** Totals clip it to
   `rangeStart`, but the needs-fixing row shows the full, unclipped duration.
   Covered by Task 3 `uses the unclipped start for needs-fixing but clips
   totals`.
4. **A browser sends a bad or missing `timeZone`.** The query falls back to
   UTC and never returns a 500. Covered by Task 4 `resolveTimeZone` unit
   tests and the e2e test `accepts an invalid timeZone`.
5. **The user is removed from an organization.** Its checks vanish from the
   very next query. Covered by Task 4 e2e `drops an organization the user no
   longer belongs to`.

- [ ] **Step 3: Add the Prisma model and write the migration**

  Prisma model:

  ```prisma
  model CheckOutage {
    id        String    @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
    checkId   String    @map("check_id")
    check     Check     @relation(fields: [checkId], references: [id], onDelete: Cascade)
  ```

  Migration, wrapped in `BEGIN; … COMMIT;` like
  `20260731120000_enforce_one_project_per_organization`:

  1. The `CREATE TABLE` and FK that Prisma would generate for the model.
  2. The `(check_id, started_at)` index.
  3. `CREATE UNIQUE INDEX "check_outages_one_open_per_check" ON
     "check_outages"("check_id") WHERE "ended_at" IS NULL;`
  4. `CREATE TABLE "check_outage_backfill_cutoff" ("cutoff" TIMESTAMP(3) NOT NULL);`
  5. The trigger function and trigger:

  ```sql
  CREATE FUNCTION record_check_outage() RETURNS trigger LANGUAGE plpgsql AS $$
  BEGIN
    IF NEW.status = 'DOWN' AND (TG_OP = 'INSERT' OR OLD.status IS DISTINCT FROM 'DOWN') THEN
      INSERT INTO check_outages (check_id, started_at)
      VALUES (NEW.id, now() AT TIME ZONE 'UTC')
      ON CONFLICT (check_id) WHERE ended_at IS NULL DO NOTHING;
    ELSIF TG_OP = 'UPDATE' AND OLD.status = 'DOWN' AND NEW.status <> 'DOWN' THEN
      UPDATE check_outages SET ended_at = now() AT TIME ZONE 'UTC'
      WHERE check_id = NEW.id AND ended_at IS NULL;
    END IF;
    RETURN NULL;
  END $$;

  CREATE TRIGGER checks_record_outage
    AFTER INSERT OR UPDATE OF status ON checks
    FOR EACH ROW EXECUTE FUNCTION record_check_outage();
  ```

  6. After the trigger exists:
     `INSERT INTO check_outage_backfill_cutoff VALUES (clock_timestamp() AT TIME ZONE 'UTC');`

     It goes after `CREATE TRIGGER` because that statement waits for
     in-flight status writers. So every transition committed before the
     cutoff predates the trigger.

- [ ] **Step 3: Write the migration**

  Use one transaction (`BEGIN; … COMMIT;`) with the phases below in this
  order.

  **(a) Reconstruct closed outages without locking `checks`.**

  Read `check_events` joined to `checks`. Use window functions over
  `PARTITION BY check_id ORDER BY timestamp, id` to get the previous and
  next event's status and timestamp.

  - `active` is true when `type IN ('HTTP','TCP','PING') AND
    interval_seconds IS NOT NULL`. Only then:
    - `gap_before` is true when the gap from the previous event is greater
      than `GREATEST(3*interval_seconds, 300)` seconds.
    - `gap_after` is the same test against the next event.
  - Among `DOWN` rows:
    - A streak **starts** where the previous status is not `DOWN` or
      `gap_before` is true.
    - It **ends** at a row whose next status is not `DOWN`, or whose
      `gap_after` is true, or which has no next event.
    - Number streaks with a running `SUM(starts::int)`.
  - For each streak, `started_at` is its first DOWN timestamp. `ended_at` is:
    - last DOWN + `interval_seconds` when `gap_after` is true;
    - otherwise the next event's timestamp;
    - **unterminated** when there is no next event.
  - Keep only streaks whose `started_at < cutoff`. Later streaks belong to
    the trigger.
  - `INSERT` the terminated streaks.
  - Write the unterminated ones, as `(check_id, started_at)`, to a
    `TEMP TABLE backfill_unterminated ON COMMIT DROP`.

  **(b)** `LOCK TABLE "checks" IN SHARE ROW EXCLUSIVE MODE;`

  This blocks status writers only for phases (c) to (e), which touch few
  rows.

  **(c) Resolve unterminated streaks** against live data:

  - If the first `check_events` row with `timestamp > started_at` and
    `status <> 'DOWN'` exists, insert the closed outage
    `[started_at, that timestamp]`.
  - Otherwise, if the check's status is `DOWN`, insert an open outage at
    `started_at` with `ON CONFLICT (check_id) WHERE ended_at IS NULL DO
    NOTHING`.
  - Otherwise, insert a closed outage ending at `checks.updated_at`.

  Then insert an open outage at `COALESCE(last_event_at, updated_at)` for
  every `DOWN` check that still has no open outage.

  **(d) Merge overlapping outages per check** with gaps-and-islands:

  - Order rows by `started_at`.
  - A new island starts when `started_at > MAX(COALESCE(ended_at,
    'infinity'))` over the earlier rows.
  - Replace each island of 2 or more rows with one row:
    `MIN(started_at)`, plus `NULL` if any row is open, else `MAX(ended_at)`.
  - Delete the island's rows before inserting the merged row, so the
    partial unique index never sees two open rows.

  **(e)** `DROP TABLE "check_outage_backfill_cutoff";`

**Interfaces:**

- Produces the following, all exported from `overview-aggregate.ts`:

```ts
export type OverviewRangeKey = 'DAY' | 'WEEK' | 'MONTH' | 'QUARTER';
export const RANGE_SECONDS: Record<OverviewRangeKey, number>; // 86400, 604800, 2592000, 7776000

export interface AggregateCheck {
  id: string; organizationId: string; type: string; status: string;
  createdAt: Date; lastEventAt: Date | null;
  periodSeconds: number | null; graceSeconds: number | null;
  schedule: string | null; tz: string | null;
}
export interface AggregateOutage { checkId: string; startedAt: Date; endedAt: Date | null }
export interface AggregateInput {
  now: Date; rangeStart: Date;
  bucketStarts: Date[];           // ascending; first may precede rangeStart
  organizationIds: string[];      // in display order (service sorts by name)
  checks: AggregateCheck[];
  outages: AggregateOutage[];     // every outage overlapping [rangeStart, now], incl. open ones
}
export interface BrokenEntry { checkId: string; state: 'DOWN' | 'LATE'; since: Date; downAt: Date | null }
export interface OutageSpanResult { startedAt: Date; endedAt: Date | null }   // clipped to range
export interface CheckTotals {
  checkId: string; brokenSeconds: number; outageCount: number;
  longestOutageSeconds: number; ongoing: boolean; uptimePercent: number | null;
  outages: OutageSpanResult[];
}
export interface AggregateResult {
  needsFixing: BrokenEntry[];
  summary: {
    uptimePercent: number | null; brokenSeconds: number; outageCount: number;
    ongoingCount: number; medianOutageSeconds: number | null; longestOutageCheckId: string | null;
  };
  buckets: { start: Date; brokenSeconds: number }[];
  byOrganization: { organizationId: string; brokenSeconds: number; outageCount: number }[];
  checks: CheckTotals[];          // only checks with ≥1 outage overlapping range; brokenSeconds desc
}
export function lateState(check: AggregateCheck, now: Date): { since: Date; downAt: Date } | null;
export function aggregateOverview(input: AggregateInput): AggregateResult;
```

Rules the implementation must follow (from spec §Definitions and §Rules):

- `lateState` returns non-null only when all of these hold:
  - `type === 'HEARTBEAT'`;
  - `status === 'UP'`;
  - `lastEventAt != null`;
  - `expected < now`, where `expected` is `nextCronFire(schedule, tz ?? 'UTC',
    lastEventAt)` when `schedule` is set, and `lastEventAt + periodSeconds`
    otherwise.

  It then returns `since = expected` and `downAt = expected + (graceSeconds ??
  0)`. There is no upper bound: a check past `downAt` is still late.
- `needsFixing` lists:
  - first, `DOWN` checks with `since` equal to the open outage's
    **unclipped** `startedAt`, or `lastEventAt ?? now` if no open outage was
    passed;
  - then `LATE` checks;
  - each group ordered by `since` ascending.
- Each outage is clipped to `[max(startedAt, rangeStart), endedAt ?? now]`.
  The total, median, longest, per-check, and per-org figures use clipped
  seconds. Counts include every outage overlapping the range.
- **Buckets:** bucket `i` covers
  `[max(bucketStarts[i], rangeStart), min(bucketStarts[i+1] ?? now, now)]`.
  Return `start = bucketStarts[i]`.
- **Uptime:**
  - Exclude checks that are `PAUSED`, or `NEW` with `lastEventAt === null`.
  - Monitored seconds `= max(0, now − max(rangeStart, createdAt))`.
  - `uptimePercent = 100 × (1 − broken/monitored)`, or `null` when monitored
    is 0.
- **Median:** sort clipped durations; for an even count, average the two
  middle values. Round every seconds value with `Math.round` at the end.

```graphql
enum OverviewRange { DAY WEEK MONTH QUARTER }
enum BrokenState { DOWN LATE }
type OverviewOrganization { id: ID!  name: String!  slug: String! }
type BrokenCheck { check: CheckModel!  organization: OverviewOrganization!  state: BrokenState!  since: DateTime!  downAt: DateTime  reason: String }
type OutageSpan { startedAt: DateTime!  endedAt: DateTime }
type CheckBrokenTime { check: CheckModel!  organization: OverviewOrganization!  brokenSeconds: Float!  outageCount: Int!  longestOutageSeconds: Float!  ongoing: Boolean!  uptimePercent: Float  outages: [OutageSpan!]! }
type OverviewSummary { uptimePercent: Float  brokenSeconds: Float!  outageCount: Int!  ongoingCount: Int!  medianOutageSeconds: Float  longestOutage: CheckBrokenTime }
type BrokenTimeBucket { start: DateTime!  brokenSeconds: Float! }
type OrganizationBrokenTime { organization: OverviewOrganization!  brokenSeconds: Float!  outageCount: Int! }
type AccountOverview { rangeStart: DateTime!  rangeEnd: DateTime!  organizationCount: Int!  checkCount: Int!  needsFixing: [BrokenCheck!]!  summary: OverviewSummary!  buckets: [BrokenTimeBucket!]!  byOrganization: [OrganizationBrokenTime!]!  checks: [CheckBrokenTime!]! }
# Query
accountOverview(range: OverviewRange!, timeZone: String): AccountOverview!
```

- Service: `OverviewService.accountOverview(userId: string, range:
  OverviewRangeKey, timeZone?: string, now?: Date): Promise<AccountOverview>`.
- Public service method: `OverviewService.bucketStarts(rangeStart: Date, now:
  Date, unit: 'hour' | 'day', timeZone: string): Promise<Date[]>`. It runs
  the step-4 SQL and is exposed for the DST test.
- Exported helper: `resolveTimeZone(value: string | undefined): string`.

Service behavior:

1. Load `membership.findMany({ where: { userId } })` with the organization
   (`id`, `name`, `slug`) and its project (`id`). Sort organizations by
   name.
2. Load `check.findMany({ where: { projectId: { in: projectIds } } })` and
   attach `organizationId`, mapping through the project. Nested
   `CheckModel` resolve fields (`events`, `nextExpectedAt`,
   `notificationChannelIds`) depend on these raw columns, so return full
   rows.
3. Load
   `checkOutage.findMany({ where: { checkId: { in }, startedAt: { lt: now }, OR: [{ endedAt: null }, { endedAt: { gt: rangeStart } }] } })`.
4. Get bucket starts from Postgres with `$queryRaw`:

   ```sql
   SELECT (gs AT TIME ZONE ${tz}) AS start
   FROM generate_series(
     date_trunc(${unit}, ${rangeStart}::timestamptz AT TIME ZONE ${tz}),
     ${now}::timestamptz AT TIME ZONE ${tz},
     ${'1 ' + unit}::interval) gs
   ```

   `unit` is `'hour'` for `DAY` and `'day'` otherwise.
5. Get reasons: for needs-fixing `DOWN` checks whose type is not
   `HEARTBEAT`, run one
   `SELECT DISTINCT ON (check_id) check_id, status_code, error FROM check_events WHERE check_id = ANY(${ids}) AND status = 'DOWN' ORDER BY check_id, timestamp DESC`.
   The reason is `HTTP ${status_code}` when the status code is set,
   otherwise `error`, otherwise `null`. Heartbeats and late checks get
   `null`; the frontend composes their text.
6. Run `aggregateOverview` and map its IDs back to check, organization,
   and `OverviewOrganization` objects.

`resolveTimeZone` returns `value` only when all of these hold, and `'UTC'`
otherwise:

- `value` matches `/^[A-Za-z0-9_+\-\/]{1,64}$/`;
- `new Intl.DateTimeFormat('en-US', { timeZone: value })` does not throw.

```ts
export const OVERVIEW_RANGES: { key: OverviewRangeKey; param: "24h" | "7d" | "30d" | "90d"; title: string }[];
// titles: "24 hours", "7 days", "30 days", "90 days"
export function parseRangeParam(value: string | null): OverviewRangeKey;   // unknown → "MONTH"
export function brokenDuration(entry: { state: "DOWN" | "LATE"; since: string; downAt: string | null }, now: Date):
  { value: string; caption: "down for" | "late by" | "overdue by" };
export function brokenReason(entry: { state: "DOWN" | "LATE"; reason: string | null; downAt: string | null;
  check: { type: string; lastEventAt: string | null } }, now: Date): string;
export function formatUptime(percent: number | null): string;  // null → "—"; 100 → "100%"; else 2 decimals + "%"
export function formatBrokenSeconds(seconds: number): string;  // 0 → "0m"; else formatElapsed(seconds * 1000)
export interface CheckBrokenTimeRow {
  check: { id: string; name: string; slug: string };
  organization: { id: string; name: string; slug: string };
  brokenSeconds: number; outageCount: number; longestOutageSeconds: number;
  ongoing: boolean; uptimePercent: number | null;
  outages: { startedAt: string; endedAt: string | null }[];
}
```

The two formatting helpers behave as follows:

- `brokenDuration`:
  - `value = formatElapsed(now − since)`;
  - the caption is `"down for"` for DOWN, `"late by"` for LATE with
    `now ≤ downAt`, and `"overdue by"` for LATE past `downAt`. When
    overdue, `value = formatElapsed(now − downAt)`.
- `brokenReason`:
  - **DOWN heartbeat:** `"no ping since " + formatRelativeTime(lastEventAt)`,
    or `"never pinged"` when there is no `lastEventAt`.
  - **DOWN active check:** `reason ?? "probe failing"`.
  - **LATE:** `"goes DOWN in " + formatElapsed(downAt − now)` while
    `downAt > now`, else `"should be DOWN; is the worker running?"`.
